# 01. Agent 工程师的心智模型

## 1. 什么是 Agent

普通 ChatBot 的核心动作是：

```text
用户输入 -> 模型生成 -> 返回答案
```

Agent 的核心动作是：

```text
用户目标 -> 规划 -> 选择工具 -> 执行 -> 观察结果 -> 修正 -> 完成任务
```

所以 Agent 不只是“会聊天”，而是能围绕目标持续行动。它通常具备：

- Goal：用户真正想完成的任务。
- State：任务当前进度。
- Tools：数据库、搜索、代码执行、业务 API 等外部能力。
- Memory：短期上下文和长期偏好。
- Policy：权限、安全、审批和边界。
- Eval：判断任务是否完成、是否可靠。

## 2. 大厂为什么招 Agent 开发工程师

企业内部有大量“语言 + 工具 + 流程”的工作：

- 客服：查订单、查政策、生成回复。
- 运营：查数据、看活动、写分析报告。
- 研发：读 issue、改代码、跑测试、发 PR。
- 办公：读文档、排日程、写总结、调系统。

这些场景都不是一次问答能解决的。它们需要模型理解意图，也需要后端系统真实执行。

## 3. Agent 系统的最小架构

```text
Client
  |
  v
API Server
  |
  v
Agent Orchestrator
  |        |          |
  v        v          v
LLM     Tools      Memory
  |        |          |
  v        v          v
Trace   Database   Vector Store
```

每个模块的职责：

- API Server：鉴权、参数校验、限流、返回结果。
- Orchestrator：决定下一步执行什么。
- LLM：理解、规划、生成、总结。
- Tools：真实执行查询、计算、搜索、写入。
- Memory：保存会话状态和用户偏好。
- Trace：记录每一步，方便排查和评测。

## 4. Demo 和生产系统的区别

Demo 常见写法：

```python
answer = llm("请回答用户问题：" + question)
```

生产写法需要考虑：

- 输入是否合法。
- 用户有没有权限。
- 是否需要检索。
- 检索结果是否足够。
- 是否需要调用工具。
- 工具参数是否安全。
- 模型输出是否可解析。
- 失败是否可恢复。
- 每一步是否可观测。
- 成本和延迟是否可接受。

## 5. 面试表达模板

当面试官问“你理解的 Agent 是什么”，可以这样答：

```text
我理解的 Agent 是以目标为中心的 LLM 应用系统。它不只是生成自然语言，而是维护任务状态，根据上下文进行规划，选择合适工具执行动作，再根据工具返回结果继续推理或修正，直到完成任务。工程上我会重点关注工具 schema、状态管理、权限控制、失败恢复、trace 可观测和 eval 评测，因为这些决定了 Agent 能不能从 demo 走到生产。
```

## 6. 练习

请把下面 3 个需求判断为 ChatBot、RAG 应用还是 Agent：

1. 用户问“公司年假政策是什么”，系统查员工手册后回答。
2. 用户说“帮我分析上周 GMV 下滑原因”，系统查数据库、查活动文档、做图表并生成报告。
3. 用户说“把这段文本翻译成英文”。

参考答案：

1. RAG 应用。
2. Agent。
3. 普通 LLM 应用。
