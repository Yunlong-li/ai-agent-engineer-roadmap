# 项目深挖问题

## 1. 你的项目解决了什么问题？

回答模板：

```text
我的项目解决的是企业经营分析中数据和业务规则分散、人工分析耗时的问题。用户可以用自然语言提出分析目标，系统会自动拆解任务，调用 SQL 查询指标，调用 RAG 检索业务规则，再用 Python 做统计归因，最后生成带证据和建议的结构化报告。
```

## 2. 你的技术难点是什么？

可以讲 3 个：

- SQL 安全和准确率。
- RAG 检索质量和引用可信度。
- Agent 多步执行的可控性、失败恢复和成本。

## 3. 你如何做 SQL 安全？

回答要点：

- 只允许 SELECT。
- 表白名单。
- limit 限制。
- 用户权限过滤。
- 敏感字段脱敏。
- SQL 错误返回结构化 observation。

## 4. 你如何做评测？

回答模板：

```text
我把评测拆成几个层次：工具选择准确率、SQL 正确率、RAG Recall@3、引用准确率、任务成功率、平均延迟和 token 成本。每个 eval case 会标注期望工具、期望表、期望来源和答案关键词，离线跑完后输出指标，避免只靠主观体验判断效果。
```

## 5. 如果 Agent 回答错了，你怎么排查？

排查顺序：

1. 看 trace，确认错在哪一步。
2. 如果检索错，看 query、chunk、top-k、rerank、权限过滤。
3. 如果 SQL 错，看生成 prompt、schema 信息、SQL 校验。
4. 如果工具对但报告错，看上下文拼接和生成 prompt。
5. 如果成本高，看步骤数、上下文长度、模型选择。

## 6. 面试官说“这只是套壳”，怎么回应？

回答模板：

```text
如果只是把用户问题转发给模型，那确实是套壳。但我的项目重点在工程闭环：我做了工具 schema、SQL 只读校验、业务知识 RAG、任务状态、trace、离线 eval、失败重试和成本统计。模型只是系统中的一个组件，真正的工程难点是如何让它可靠地调用业务工具、基于证据输出，并且能被评测和排查。
```
